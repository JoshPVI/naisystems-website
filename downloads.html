Getting started

Installation help

Install the Windows Agent

  1. Download and run Wake-Agent-Setup-0.4.5-win-x64.exe. If updating, first choose Quit from the existing agent’s tray menu.
  2. Confirm installation for your Windows user and choose whether to start at sign-in. No separate .NET installation is needed. The alternative ZIP uses Install-WakeAgent.cmd after extraction.
  3. The optional firewall rule needs administrator approval. It allows the agent on Private/Domain networks and the local subnet. Keep Windows security protections enabled; this beta is unsigned.
  4. Open Wake Agent from Start. One eligible physical private network connects automatically. If a choice is needed, select the correct network on Overview and choose Connect. Use a trusted private network.

Install the Android beta

  1. On your Android phone, choose Download Android beta above and open the APK. Install over the existing Wake app to preserve its data; do not uninstall first.
  2. If prompted, allow installation from the browser used for this download; remove that permission afterwards if you no longer need it.
  3. Open Wake and connect to the same trusted network as your awake PC. No Expo Go or development server is required.
  4. Add a computer manually for basic Wake, or pair the optional Windows Agent to import its MAC address and enable approved controls.

This is a beta APK, distributed outside Google Play. Physical Android pairing, controls and Wake testing are still pending.

Local release-signed build with bundled JavaScript; no Metro or development server needed. Emulator upgrade/launch checks passed. Pixel / Android 17 re-pair and refresh acceptance remains pending. For legacy pairing keys, create a fresh invitation on the PC and pair again.

Install the iPhone beta

  1. On your already-provisioned iPhone, open the iPhone install page above for Wake 1.5.2, build 15.
  2. Use the installation instructions on that finished Expo build page. No App Store listing or public installation is available for this ad-hoc build.
  3. If your iPhone is not provisioned, contact NAI Systems about beta eligibility. Downloading a file does not register a device.
  4. For first-time setup, keep the PC awake and signed in and connect your phone to the same trusted network.

Mobile/device acceptance remains pending. This installation page does not grant public-release clearance or broaden beta eligibility.

Pair your phone with the Windows Agent

Keep the PC awake and signed in, with both devices on the same trusted LAN. In Windows, choose Pair a phone. Review the local controls: all are initially selected for a new invitation, and you can change them before approving the named phone on the PC. Scan the QR or paste the invitation into Wake’s Pair Windows Agent screen and follow the phone’s save/confirmation steps. Existing phone grants remain unchanged; internet consent is separate.

You can switch to Remote Desktop on that phone to approve, then return to Wake within five minutes. If Wake is force-quit or the agent restarts during pairing, create a new invitation.

Set up Wake-on-LAN on Windows

Work through these sections in order. Start with Ethernet and local Wake from Sleep, then test Hibernate or Shut down separately. Basic Wake needs no PC agent or account. These instructions are for Windows PCs; menus vary by model and driver.

  • 1. Connect the PC and phone
  • 2. Find the Ethernet adapter and MAC address
  • 3. Open the BIOS / UEFI settings
  • 4. Enable the BIOS wake options
  • 5. Set the Windows Ethernet driver options
  • 6. Allow the Ethernet adapter to wake Windows
  • 7. Prove local Wake from Sleep first
  • 8. Sleep works, but Shut down does not
  • 9. If local Wake still fails
  • 10. The agent times out after a power request
  • 11. Collect a useful troubleshooting report

1. Connect the PC and phone

Use Ethernet, mains power and your normal home network for the first test.

  1. Connect the PC’s Ethernet socket to the router or network switch with a cable. Leave that cable connected during sleep and shutdown. Use the built-in Ethernet socket for the first test; a USB adapter or dock needs its own documented wake support.
  2. Keep the PC connected to mains power. On a laptop, connect its charger. A PC with its power supply switched off or its smart plug disconnected cannot receive a wake packet.
  3. Connect the phone to the same home/work LAN over Wi-Fi. Avoid guest Wi-Fi and isolated IoT networks. A shared internet connection or similar Wi-Fi name does not establish that devices can communicate. Different 2.4/5 GHz bands are fine when the router bridges them to the same LAN.
  4. Use the installed Wake app, not the browser preview. For this first test choose local Wake, not Wake over internet. Router port forwarding and cloud registration are not needed for local Wake.

Wake over Wi-Fi on the PC is a different hardware capability. A Wi-Fi connection that works while Windows is awake does not prove it can receive wake packets while sleeping. Establish the wired test first.

2. Find the Ethernet adapter and MAC address

Use the address of the socket carrying the Ethernet cable, including when pairing imported an address.

  1. With the PC awake, open Start, type Terminal and open it. Run ipconfig /all. Find the connected Ethernet entry; match its Description to the adapter in Device Manager. Do not use a disconnected entry, Wi-Fi, Bluetooth, VPN or virtual adapter for this wired test.
  2. Copy that Ethernet entry’s Physical Address into the computer’s MAC address field in Wake. An address such as 00-11-22-33-44-55 is a MAC address; an address such as 192.168.1.20 is an IP address. They are different fields.
  3. If the computer was saved through agent pairing, check that the imported MAC matches the connected Ethernet adapter. Pairing authenticates power controls; it does not prove the selected adapter supports wake in every power state.
  4. Record the Ethernet IPv4 address and Subnet Mask for troubleshooting. Leave Wake’s broadcast override blank for the normal first test; it calculates the broadcast from the phone’s active Wi-Fi network. Do not copy the PC’s ordinary IP into the broadcast field.

To identify the PC/motherboard, press Windows+R, enter msinfo32 and record System Manufacturer, System Model and BaseBoard Product. Use that exact model’s support manual for BIOS settings.

3. Open the BIOS / UEFI settings

BIOS/UEFI is the PC’s startup settings screen. Here is how to reach it.

  1. Save open work and arrange physical access to the PC for the restart. BIOS setup is normally outside a Windows Remote Desktop session.
  2. Windows 11: open Settings → System → Recovery. Under Advanced startup choose Restart now. Windows 10: Settings → Update & Security → Recovery → Advanced startup → Restart now.
  3. On the recovery screen choose Troubleshoot → Advanced options → UEFI Firmware Settings → Restart. This opens the manufacturer’s settings screen.
  4. If UEFI Firmware Settings is missing, use the manufacturer’s documented startup key instead. For example, ASUS motherboards commonly use Delete and Dell PCs commonly use F2. Restart and press the model’s key while its logo appears. The manual is the authority for your PC.

Only adjust documented wake/power options. Changing boot mode, Secure Boot or TPM is not a Wake-on-LAN setup step. Have access to your device recovery information before entering recovery/firmware settings.

Microsoft: reaching UEFI settings

4. Enable the BIOS wake options

Look for Wake on LAN, PME or Power On By PCI-E; the names and locations vary.

  1. Check the model’s manual for wake support and its supported states. Open its Power, Power Management, Advanced or APM menu. Enable the documented option, often called Wake on LAN, Wake by PME, Resume by LAN or Power On By PCI-E/PCI.
  2. ASUS motherboard example only: Advanced Mode → Advanced → APM Configuration → Power On By PCI-E → Enabled. Dell example only: System Management → Wake on LAN; choose the appropriate LAN option. These are examples, not universal menu paths.
  3. Check whether the model’s instructions require disabling ErP/EuP or Deep Sleep for the power state being tested. Such settings can remove standby power from the Ethernet controller. Change them only where the manufacturer documents the relationship.
  4. Choose Save Changes and Exit, review the listed changes and confirm. Many boards use F10, but follow the displayed controls. Let Windows boot fully before continuing. Network/PXE boot is not the same setting as waking a powered-down PC.

There may be separate options for wake from Sleep and wake after shutdown. Enabling one does not guarantee the other.

5. Set the Windows Ethernet driver options

Enable magic-packet wake on the same adapter whose MAC you saved.

  1. Right-click Start → Device Manager. Expand Network adapters. Right-click the Ethernet controller identified in section 2 and choose Properties.
  2. Open Advanced. Select Wake on Magic Packet and set its Value to Enabled if offered. Some drivers also expose Enable PME. For shutdown testing, check model-specific options such as Shutdown Wake-On-Lan, Shutdown Wake Up or Wake from power off and enable the applicable option.
  3. If the manufacturer’s troubleshooting instructions say to disable Energy-Efficient Ethernet or Green Ethernet, record the original value, change that one setting and retest. It is a driver/model-specific troubleshooting step, not a universal requirement.
  4. Choose OK to apply changes. If the required setting is absent, check the exact PC/motherboard’s Ethernet driver and supported wake states on its official support page. A missing option is not a reason to change an unrelated adapter or install a random driver utility.

Settings differ between Intel, Realtek and other controllers, and between driver versions. A checkbox can request wake support; it cannot add hardware support.

Intel: Ethernet driver wake settings

6. Allow the Ethernet adapter to wake Windows

Check the Power Management tab; missing tabs need model-specific guidance.

  1. In the same Ethernet Properties window, open Power Management if available. Select Allow this device to wake the computer. Where available, select Only allow a magic packet to wake the computer to restrict wake triggers.
  2. Do not automatically clear Allow the computer to turn off this device to save power. Some Ethernet drivers require it checked for their wake configuration. Follow the driver/PC maker’s instructions for that control.
  3. If the tab or controls are missing/greyed out, check the official driver and the PC’s sleep model. Modern Standby PCs can expose different controls. Do not apply registry hacks to force a tab to appear.
  4. Select OK. If the driver asks for a restart, save work and restart before testing.

An administrator account may be needed to apply driver or power-setting changes.

7. Prove local Wake from Sleep first

This separates basic packet delivery from shutdown-specific behaviour.

  1. Save your work. Leave Ethernet and mains power connected. Use Windows Start → Power → Sleep on the PC for the first test, so a remote shutdown/control problem is not part of the test.
  2. Wait 30–60 seconds for the PC to settle. On the phone, stay on the same normal Wi-Fi and tap Wake for the saved Ethernet MAC.
  3. Allow time for the PC to resume. The Windows sign-in screen counts as a successful wake: sign in with your Windows PIN, password or Windows Hello. Wake does not enter Windows credentials or unlock the session. Packet sent means transmission, not confirmed wake; an Unknown badge alone does not establish failure.
  4. Record the result as Sleep → Wake passed or failed. Test Hibernate and Shut down separately only after this baseline. If Sleep is unavailable, run powercfg /a and consult the PC’s supported sleep-state instructions.
  5. Optional — return to the desktop after sleep: in Windows Settings → Accounts → Sign-in options → Additional settings, find If you’ve been away, when should Windows require you to sign in again? Choose Never if offered. On Windows 10 look for Require sign-in → Never. This removes the sign-in check after sleep; device/account policies may restrict it. To restore the check, select the sleep/require-sign-in option again.
  6. Optional — automatic login after a full boot: use Microsoft’s Sysinternals Autologon instructions linked below. Where supported, run the tool, review the account/domain, enter that Windows account’s password directly in the tool and choose Enable. The password is not the Windows Hello PIN. Disable in the same tool to undo it. Wake does not collect these credentials or configure this setting.
  7. These are different Windows behaviours: skipping sign-in after sleep, logging in after boot and unlocking a deliberately locked session. An explicit Windows Lock still requires Windows authentication; neither wake packets nor startup Autologon are a remote-unlock command.

A working Sleep test does not establish wake after shutdown. Choosing Never allows someone at the PC to resume the session. Autologon stores a Windows sign-in secret which an administrator can recover; use it only if you want that tradeoff. Keep someone able to use the power button during initial tests.

8. Sleep works, but Shut down does not

Windows Fast Startup is a useful check when Sleep wakes successfully but shutdown does not.

  1. Check the PC/adapter manual specifically for wake from shutdown (S5), not just Sleep (S3) or Hibernate (S4). Windows does not generally arm standard WoL after Fast Startup or full shutdown; some firmware/adapter combinations provide their own support.
  2. Check the BIOS shutdown wake/ErP/Deep Sleep options and the Ethernet driver’s shutdown wake option described above. Leave mains power connected. Ethernet link lights can be a clue to standby power, but are not proof that wake is configured correctly.
  3. If your manufacturer recommends testing with Fast Startup disabled: open Control Panel → Hardware and Sound → Power Options → Choose what the power buttons do → Change settings that are currently unavailable. Clear Turn on fast startup (recommended), choose Save changes, then perform a fresh shutdown test. Record the original setting so it can be restored.
  4. Disabling Fast Startup changes shutdown/startup behaviour and may slow startup. It does not create shutdown wake support. If the option is missing or shutdown wake is unsupported, use a successfully tested Sleep state rather than assuming the app can override the hardware.

The Windows checkbox is called Turn on fast startup; it is separate from a BIOS setting called Fast Boot. For a controlled comparison after changing it, shut down manually from Windows, leave Ethernet/mains connected and try Wake. This is a test, not a guaranteed fix. Agent disappearance is not confirmation of shutdown.

9. If local Wake still fails

Check the MAC, LAN path and packet delivery before changing more settings.

  1. Turn the PC on manually. Recheck the saved MAC against the connected Ethernet controller and confirm the cable and router/switch link work. If pairing used another adapter, correct the saved wake target.
  2. Recheck phone Wi-Fi, guest/client isolation, VLAN separation and any VPN route. Try the normal same-LAN configuration. A successful agent connection while awake confirms that connection only; it does not prove broadcast wake packets reach the sleeping Ethernet controller.
  3. If a broadcast override was entered, record it and try the normal automatic setting on the shared LAN. For a deliberate override, calculate it from the actual subnet mask; do not assume every network ends in .255. Confirm the configured UDP port is the intended wake port, not the agent’s HTTPS control port.
  4. For a technician: while the PC is awake, capture incoming packets on its Ethernet interface while tapping Wake and check for a magic packet containing its MAC. Compare another sender on the same LAN using the same MAC/broadcast/port. A capture while awake isolates the send/network path; it does not prove reception while the NIC is in a low-power state.
  5. If packets arrive while awake but the matching Sleep test still fails, focus on driver, wake arming and the model’s supported state. If packets do not arrive, focus on phone permissions, destination and network delivery. Collect the details in section 11 instead of changing several settings at once.

Local Wake does not require opening router internet ports or disabling the Windows firewall. Do not expose the agent’s control listener as a Wake troubleshooting step.

10. The agent times out after a power request

A lost connection is an unconfirmed outcome, not proof of shutdown or a new Wake failure.

  1. Read the report timestamp. Online/uptime may describe a previous successful check while the current power-control connection has failed. They are separate observations.
  2. A timeout to TCP 49270 means the phone could not reach the agent’s control listener at that address. The PC may be asleep/off, logged out, disconnected, running a stopped agent or blocked from that connection. It does not identify which cause occurred.
  3. If a pending request remains after contact is lost, do not assume it is still cancellable or submit the same power action again. Its last received state is not its confirmed final outcome. Check the PC directly where possible, then refresh once the agent is running.
  4. After signing in, open Wake on Windows or check the start-at-sign-in option chosen during installation. The current agent runs in its user’s session, not before login. Confirm it is connected to the correct private network, then refresh the phone’s controls.

Wake packets and agent HTTPS requests are different paths. A timeout to the agent’s control port does not show whether a wake packet was sent, delivered or accepted.

11. Collect a useful troubleshooting report

Record the model, exact power state, addresses and a few read-only Windows checks.

  1. Record PC/motherboard model, Windows version (Windows+R → winver), Ethernet controller name and Driver tab version, phone model/OS and Wake app version.
  2. State the tested transition: Sleep, Hibernate or Shut down → local Wake. Include Ethernet versus Wi-Fi, mains power, phone’s local Wi-Fi versus mobile data, and whether Sleep → Wake ever works.
  3. In Windows Terminal run powercfg /a to list available sleep states, powercfg /devicequery wake_armed to list devices currently armed for sleep wake, and powercfg /lastwake after resuming to inspect the last reported wake source. These are read-only checks; they do not establish S5 support or prove a packet arrived.
  4. Include the relevant Ethernet entry from ipconfig /all, the saved MAC, any broadcast override, UDP port, the test time and the exact app error. Share only the relevant fields; keep pairing invitations, recovery keys and unrelated device/account identifiers private.

If the last wake was the power button, that is not evidence of a successful magic-packet wake.

12. Test internet Wake only after local Wake works

Direct internet Wake has additional router/ISP requirements; cloud status does not deliver Wake.

  1. Use a power state that passed the local test. Follow the router model’s instructions for a reachable public IPv4 address and UDP mapping that can deliver to the sleeping PC; some routers need an IP-to-MAC binding. A DHCP reservation alone does not prove that path.
  2. In Edit computer, set the public IPv4 address and external mapped UDP port. Test Wake over internet using mobile data. CGNAT, an address change, router restrictions or expired delivery information can prevent it.
  3. Do not forward the Windows agent’s control ports. The current cloud feature provides encrypted status/history, not internet power commands or an awake-device wake helper. See Setup & privacy for the full internet/Wake+ guide.

Installing or pairing the agent cannot make a sleeping/off PC receive commands through that agent.

Optional cloud beta and private invitations

Cloud status and history are invitation-only. Request access from NAI Systems; invitation codes are supplied privately. A cloud beta code is separate from the temporary QR invitation used to pair a phone.

If invited, enter your code in Windows Agent Settings → Use invitation, enable sharing on Overview and wait for Cloud status synced. Refresh the paired computer’s Controls once on your home network so the phone receives its own cloud credentials.

After syncing, use Save cloud recovery key and store the file privately somewhere accessible without the PC. Keep codes, pairing invitations and recovery files private. Cloud status does not wake a sleeping PC or deliver power commands; those controls stay local.

Beta limits, updates and removal

The Windows Agent runs in your signed-in session, with no service before login or automatic updates. Closing its window leaves it in the tray; Quit stops it. If the PC address changes, restart on the correct adapter and pair again.

Save your work before testing power actions. Hibernate-to-Wake is unresolved, and Android hardware validation remains pending. Status and history may be delayed; Unknown does not prove that a computer is off.

To remove the agent, revoke phones first if you want to remove their access, quit the tray app, then use Windows Installed apps. Uninstall retains pairing data. Revoking a phone’s cloud access requires a successful sync; if the PC is unavailable, use your saved recovery file through Wake’s recovery help to disable its cloud registration.
